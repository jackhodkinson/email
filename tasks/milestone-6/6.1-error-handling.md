# Task 6.1: Error Handling

**Milestone**: 6 - Polish & Robustness
**Status**: Todo
**Dependencies**: Milestones 1-5
**Blocks**: None

## Goal

Gracefully handle all error scenarios with user-friendly feedback.

## Context

- Auth failures, API errors, network issues
- Database errors
- User should never see raw errors

## Requirements

### 1. Error Types to Handle

| Error | Handling |
|-------|----------|
| OAuth rejected | Show message, prompt re-auth |
| Token expired | Auto-refresh, or prompt re-auth |
| Gmail API 429 | Backoff, retry, show "rate limited" |
| Gmail API 5xx | Retry with backoff |
| Network offline | Show offline indicator |
| Database error | Show generic error, log details |
| Unknown | Log, show generic message |

### 2. Error Boundary

Create React error boundary for unexpected errors:
```typescript
export function ErrorBoundary({ children }) {
  // Catch and display fallback UI
}
```

### 3. API Error Handling

```typescript
// Wrapper for server functions
async function withErrorHandling<T>(fn: () => Promise<T>): Promise<T> {
  try {
    return await fn();
  } catch (error) {
    // Categorize and handle
  }
}
```

### 4. User Feedback

- Toast notifications for transient errors
- Inline errors for form validation
- Full-page error for critical failures

## Acceptance Criteria

- [ ] No raw errors shown to users
- [ ] Auth errors prompt re-auth
- [ ] Network errors indicated
- [ ] Retry available where appropriate
- [ ] Errors logged for debugging
