# Task 2.2: Safe HTML Rendering

**Milestone**: 2 - Read an Email
**Status**: Todo
**Dependencies**: 2.1 Email Detail Route
**Blocks**: 2.4 Navigation

## Goal

Safely render HTML email content with inline images while preventing XSS attacks.

## Context

- Many emails contain HTML formatting
- Must sanitize to prevent XSS
- Need to handle inline images (cid: references)
- See [ARCHITECTURE.md](../../ARCHITECTURE.md#security-considerations)

## Requirements

### 1. Install DOMPurify

```bash
bun add dompurify
bun add -d @types/dompurify
```

### 2. Create Sanitization Utility (`src/lib/sanitize.ts`)

```typescript
import DOMPurify from "dompurify";

export function sanitizeHtml(html: string): string {
  return DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ["p", "br", "b", "i", "u", "a", "img", "div", "span",
                   "table", "tr", "td", "th", "ul", "ol", "li", "h1",
                   "h2", "h3", "h4", "blockquote", "pre", "code"],
    ALLOWED_ATTR: ["href", "src", "alt", "style", "class"],
    ALLOW_DATA_ATTR: false,
  });
}
```

### 3. Email Content Component

- Render sanitized HTML using `dangerouslySetInnerHTML`
- Apply base styles for email content
- Handle both HTML and plain text bodies

### 4. Styling

- Constrain email content width
- Style links, images appropriately
- Handle quoted replies (blockquote styling)

## Acceptance Criteria

- [ ] HTML emails render with formatting intact
- [ ] Malicious scripts are stripped
- [ ] Links work and open in new tab
- [ ] Images display (external URLs)
- [ ] Plain text emails display properly
- [ ] No XSS vulnerabilities

## Technical Notes

- DOMPurify runs client-side (sanitize before inserting into DOM)
- External images may be blocked by email sender's tracking
- Future: proxy images through backend to avoid tracking
